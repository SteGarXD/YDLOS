# RLS для wizard (без QL-чартов)

QL-чарты вам **не нужны**, если вся аналитика собрана в конструкторе на датасетах.

## Откуда берётся `__user_id`

При любом запросе данных (wizard или QL) UI-сервер дописывает в параметры:

- `__user_id` — id пользователя в `datalens-auth`;
- `__embed` — признак embed-режима.

Патч: `charts-engine/controllers/run.ts` в overlay (кандидат в upstream).

## Что сделать в датасете

1. В DWH — `dim_user_scope` (связь пользователя с `airline_id` / группой рейсов).

2. В датасете — параметр с именем **`__user_id`**, тип Integer. Пользователь его не вводит; значение приходит с сервера.

3. В SQL источника датасета — условие, например:

```sql
WHERE airline_id IN (
  SELECT airline_id FROM dim_user_scope WHERE auth_user_id = {{__user_id}}
)
```

4. Все wizard-чарты на этом датасете автоматически ходят с фильтром.

Селекторы на дашборде (период, аэропорт и т.д.) — отдельно. Ограничение «только своя авиакомпания» держите в SQL датасета.

## Два слоя (не путать)

| Слой | Инструмент |
|------|------------|
| В списке воркбука видны только «свои» дашборды | US: read на entry дашборда |
| Внутри дашборда — только свои строки | Параметр `__user_id` в датасете |
