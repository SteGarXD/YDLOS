# Доступ к дашбордам и к данным — как в open source DataLens

Два разных слоя. Их не смешивают.

## 1. Кто какой дашборд видит в списке воркбука

Это **права United Storage** на объекты (entry): дашборд, датасет, подключение.

Как у datalens-tech:

- Роль **`datalens.admin`** (вы) — полный доступ, в воркбуке видны **все** дашборды.
- Роль **`datalens.viewer`** (пользователи с Keycloak) — только просмотр; **какие именно дашборды** в списке воркбука — решает US, не роль viewer сама по себе.

Практика для портала:

1. Один воркбук «Портал».
2. Пользователям выдаёте **read** на воркбук (чтобы открыть страницу воркбука).
3. На **каждый дашборд**, который им можно, — отдельно **read** в US (в UI «Доступ» / Share, или скриптом `sync-us-permissions` при 50–100 авиакомпаниях).

Пользователь без read на дашборд **не увидит** его в таблице/списке внутри воркбука. Админ видит всё — это нормально.

Это **не** `pd_projects` и **не** отдельный RBAC-сервис. Так задумано в OSS: auth (роли) + US (объекты).

### OSS YDLOS: как выдать read на дашборд

В US overlay плагин **DLS** (ACL на entry) пока **заглушка** — автоматического API «выдать read пользователю X на entry Y» нет.

Операционно:

1. **UI «Доступ»** на каждом дашборде (Share overlay) — для десятков связок.
2. **`integration/sync-us-permissions.sh`** — проверяет CSV (логин ↔ entry_id), пишет чеклист `MANUAL_SHARE_UI` для массовой раздачи.
3. **Матрица авиакомпаний:** `examples/portal/dashboard-mapping.csv` + `airline-users.csv`.

Альтернатива до появления upstream DLS: отдельный воркбук на авиакомпанию и свой iframe URL (проще ACL на уровне воркбука).

## 2. Какие строки внутри дашборда (рейсы, группы)

Это **не** US. Даже если два пользователя видят один и тот же дашборд, без фильтра в данных оба увидят **все** строки.

Делается в **датасете** (у вас всё через wizard — без QL-чартов):

1. Таблица `dim_user_scope` в DWH (auth_user_id ↔ airline_id).
2. В датасете параметр **`__user_id`** (Integer).
3. В SQL источника датасета — фильтр через `dim_user_scope`.

Сервер подставляет `__user_id` при запуске **любого** чарта (wizard тоже). Подробнее: [wizard-rls-parametry-dataset.md](wizard-rls-parametry-dataset.md).

Селекторы на дашборде — для бизнеса (даты, маршруты). **Не** заменяют RLS.

## 3. iframe с портала

Открывайте **страницу воркбука**, не отдельный дашборд:

```text
https://<bi-host>/workbooks/<workbookId>
```

Там список дашбордов (то, что разрешено US). После SSO пользователь попадает сюда, без лишней страницы входа — см. [oidc-seamless-sso.md](oidc-seamless-sso.md).

## Сводка

| Вопрос | Механизм |
|--------|----------|
| Админ видит все дашборды | `datalens.admin` |
| Пользователь видит только свои дашборды в списке | US read на entry дашборда |
| Пользователь видит только свои рейсы в графиках | Параметр `__user_id` в датасете + DWH |
| Нужны ли QL-чарты | Нет, если фильтр в датасете |
